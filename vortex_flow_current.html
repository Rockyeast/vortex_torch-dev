9 个内置策略 — algorithms.py

三问法：cache 存什么摘要 → q 如何打分 → topK 选页。点标签切换策略详情。

"block_sparse_attention" BlockSparseAttention
__init__ 声明算子

self.cmean = CMean()
self.gemm = GeMM()
self.topk = TopK(k=…)

实现要点

head 维先 Mean 聚合，再用 GeMM 批量点积。所有 page 一次矩阵乘，O(S·D) 复杂度。最轻量基线策略。

约束/注意

无特殊约束。CMean dim=1 在 token 维做 reduce。每算子实例独占，禁止复用同一 self.cmean。

"gqa_block_sparse_attention" GQABlockSparseAttention
__init__ 声明算子

self.cmean = CMean()
self.gemm = GeMM()
self.softmax = Softmax()
self.maxh = Max()
self.topk = TopK(k=…)

实现要点

GeMM 保留 H_q 维，每 head 独立与 centroid 打分，Softmax 温度 0.09 锐化分布，Max 跨 head 聚合取最强信号。

约束/注意

无特殊约束。Softmax 温度可调。Max dim 须对应 H_q 轴。适合 GQA 模型（多 q head 共享 k/v head）。

"gqa_quest_sparse_attention" GQAQuestSparseAttention
__init__ 声明算子

self.cmax = CMax()
self.cmin = CMin()
self.kron = Kron()
self.sum = Sum()
self.maxh = Max()
self.topk = TopK(k=…)

实现要点

Kron 实现 QUEST 上界 max(q·M, q·m)，Sum 沿 D 求和得 per-page 上界，Max 跨 head 聚合。无需 centroids，边界更紧。

约束/注意

无特殊约束。cache 存储翻倍（max+min）。Kron 要求 max/min 与 q 形状兼容。Sum dim 须指定 D 轴。

"lserve_sparse_attention" LServeSparseAttention
__init__ 声明算子

self.cmax = CMax()
self.cmin = CMin()
self.kron = Kron()
self.sum = Sum()
self.maxh = Max()
self.topk = TopK(k=…)

实现要点

create_cache 须声明 n_sub 个 sub-block（每块 16 tokens）。Max 同时跨 H_q 和 n_sub 聚合，取 page 内最强 sub-block。

约束/注意

cache 存储 = 2×n_sub×D per page，大于 GQAQuest。n_sub 须与 block_size/16 一致。Max 须同时指定 H_q 和 n_sub 轴。

"lserve_centroid_sparse_attention" LServeCentroidSparseAttention
__init__ 声明算子

self.cmean = CMean()
self.gemm = GeMM()
self.mean = Mean()
self.maxsub = Max()
self.topk = TopK(k=…)

实现要点

Mean 先聚合 head，GeMM 对所有 sub-block centroid 打分，Max 取最强 sub-block。存储仅 n_sub×D（无 max/min 翻倍）。

约束/注意

无特殊约束。n_sub 须与实际 sub 划分一致。Max dim 须对应 n_sub 轴。centroid 不如 max/min 上界严格，可能漏选。

"masked_quest_sparse_attention" MaskedQuestSparseAttention
__init__ 声明算子

self.cmax = CMax()
self.cmin = CMin()
self.kron = Kron()
self.mask = MaskSlice()
self.sum = Sum()
self.maxh = Max()
self.topk = TopK(k=…)

实现要点

MaskSlice 将 QUEST 上界张量的前 8 维归零，去除 RoPE / sink 位置信号对分数的干扰，让内容语义主导选 page。

约束/注意

MaskSlice 的 slice 范围须匹配 head_dim 约定（前 8 维为位置编码集中区域）。不依赖 ctx，mask 是静态的。

"centered_block_sparse_attention" CenteredBlockSparseAttention
__init__ 声明算子

self.cmean = CMean()
self.gemm = GeMM()
self.mean = Mean()
self.submean = SubMean()
self.topk = TopK(k=…)

实现要点

SubMean(dim=0) 计算所有 page score 的均值并减去，相当于选"相对高分"的 page，去除 q 本身方向上的全局偏置。

约束/注意

无特殊约束。dim=0 reduce 将 RAGGED → BATCHED，需注意后续 topK 接收 BATCHED 形状。适合 score 分布不均匀的场景。

"running_avg_block_sparse" ⚠ Save/Load RunningAvgBlockSparse
__init__ 声明算子

self.cmean = CMean()
self.gemm = GeMM()
self.load = Load()
self.save = Save()
self.mean = Mean()
self.topk = TopK(k=…)

实现要点

Load 取出上步 r_score，与当前 dot(q̄,c) 加权求和（EMA），Save 写回持久化。跨 step 累积访问热度，偏好历史高频块。

约束/注意

⚠ engine JSON 必须设 disable_radix_cache: true，否则 prefix cache 会共享 r_score 导致跨请求污染。CFill(0) 初始化新 block。

"venergy_gated_centroid" VEnergyGatedCentroid
__init__ 声明算子

self.cmean_k = CMean()
self.cmean_v = CMean()
self.gemm = GeMM()
self.mean = Mean()
self.mul = Multiply()
self.topk = TopK(k=…)

实现要点

v_energy 由 cache["v"] 的 L2 均值自动计算，Mul 将 q·k 分数按 v 能量加权。低能量 page（v≈0）被压低，高信息量 page 被优先选。

约束/注意

无特殊约束。v_energy 自动由 cache["v"] 计算，无需手动声明。CMean 须两个独立实例（cmean_k 和 cmean_v 分开）。

写新策略注意：每个算子实例不能复用 | forward_indexer 禁 native torch ops | score 必须 RAGGED [S,1,1] | Save/Load 须设 disable_radix_cache: true | dim=0 reduce 把 RAGGED 变为 BATCHED

ctx / metadata 运行上下文

这里连接两种生命周期：Context 保存编译期固定信息，metadata 保存每轮 batch 会变的布局，memory_pool 保存真正的 K/V 和策略摘要。

① 一次构建，逐轮复用

Context.create()固定 shape、page/block、backend、图账本
静态 ctx整个 compiled indexer 生命周期复用同一个对象
MetaData.preallocate()按 backend 一次性申请可复用 buffer
profile + compile生成 compiled_indexer / compiled_cache
ctx.metadata = md静态对象持有动态 buffer 容器
decode batchq、seq_lens、req_indices、page loc
planner 刷 metadata只改内容，不重新分配 buffer
compiled_indexer读取 q、摘要和本轮布局，计算选页
后端所需 page 表CSR indices 或 block_table + seqlens
attention backend只读取选中 page 的真实 K/V
compiled_cache新 K/V 到来后更新 page 摘要
memory_pool真实 K/V + centroids/max 等策略摘要

② 三类对象不要混在一起

Context：固定说明书

保存容量、形状、backend 和编译图。创建后不会随 batch 改变。

metadata：本轮地址表

buffer 指针固定，但每轮填入不同 indices、block tables 和 workload。

memory_pool：真实仓库

保存每个 page 的 K/V 数值和策略额外摘要，attention 最终从这里取值。

三种张量格式

理解 BATCHED / PAGED / RAGGED 是读懂算子行为的关键。框架会自动管理格式转换。

BATCHED

按 (batch_id, kv_head_id) 索引

用途：query q、Reduce(dim=0) 输出

形状：[B×H_kv, D0, D1]

每个 (batch, head) 恰好一行

示例：q_mean = Mean(dim=1)(q) → [B, 1, head_dim]，D0=1 已被压掉

PAGED

按绝对 block ID 索引

用途：cache 字段（k, v, centroids 等）

形状：[total_blocks, D0, D1]

同一 block 行可被多个序列共享

示例：cache["centroids"] → [total_blocks, 1, D] PAGED

RAGGED

按 (batch, head) 的扁平块列表索引

用途：indexer 中间量、最终 score

形状：[Σ blocks_i, D0, D1]

用 dense_kv_indptr CSR 指针分段

示例：score = GeMM(q_mean, centroids) → [S, 1, 1] RAGGED

格式转换规则
PAGED → RAGGED

自动发生：cache 字段在 indexer 中读取时，通过 dense_kv_indices 按 page table 展开为 RAGGED

RAGGED → BATCHED

Reduce(dim=0) 触发：沿 S 轴按 indptr 分段聚合，每 (batch, head) 输出一个值

BATCHED → RAGGED

广播：BATCHED 值对其关联的所有 RAGGED 行重复广播

CSR 寻址结构

dense_kv_indptr[b*H_kv + h] = 该 (batch, head) 在 RAGGED 轴的起始位置（CSR 指针）
dense_kv_indices[ragged_idx] = 扁平块列表，ragged 位置 → 绝对 block_id（PAGED 行号）
sparse_kv_indptr / sparse_kv_indices = topK 之后的稀疏版本（给 FlashInfer/TRTLLM 消费）
工作负载按 workload_chunk_size 分块：winfo_q_indices / winfo_kv_offsets / winfo_kv_lens

Plugin 是什么

整个 Vortex 扩展。由 package entrypoint 被 SGLang 发现，一个 plugin 可以注册多个 hook。

Hook 是什么

一条 target + wrapper + HookType 的接线关系。Vortex plugin 一共注册八条。

Wrapper 是什么

plugin.py 中被 HookRegistry 直接调用的函数，知道原 SGLang 函数及 AFTER/AROUND 语义。

Integration 是什么

wrapper 调用的普通运行时函数集合，负责 flow、KV pool、显存大小和 backend 注册。

GPU 调度策略

free_gpus.sh

打印空闲 GPU 索引（无计算进程 & memory.used < 1024 MiB）。每次启动前都重新探测——集群是共享的，不能假设固定编号。exit 1 = 无空闲 = 强制等待。

TP × MAX_GPUS 分配

每个 variant 占用 tp_size 块 GPU。同时运行数 = floor(min(free, MAX_GPUS) / TP)。可用 GPU < TP → 等待；每波结束后重新检测空闲。

每批固定 4 个变体

4 变体保证正交 knob sweep 和 Pareto 采样密度。GPU 不足时分多波跑完，但 batch 总数不变。不允许在第一批跑完前发射第二批（OOM 风险）。

CUDA_VISIBLE_DEVICES 隔离

每个子进程拿到连续的 TP 块 GPU 切片，通过 CUDA_VISIBLE_DEVICES 隔离，互不干扰。日志写 logs/submission/<TAG>_batch_<N>/。

优化目标：(throughput, mean@16) Pareto 前沿

无固定质量底线

不是"达到某分数就好"。目标是把 (throughput, mean@16) 二维平面上的 Pareto 前沿向外推。既买速度又买精度的变体都算赢。

knob 分配策略

精度偏向：宽松 topk_val、少 layers_skip、bf16 KV。速度偏向：紧 topk、多 layer skip、fp8 KV、approxTopK(tolerate_ratio>0)、mem_fraction_static→0.9。

novelty 配额

每批 ≥ 1 个 novelty slot（§16.2 未试 knob / §16.3 反转 / §16.4 第一性原理）。其余 2–3 个用 catalog 参数扫描给 novelty 提供对比基线。

memory.md §5 winners

只有在当前 Pareto 前沿上的变体才进 winners。新跑分要和 §5 对比，而不是和固定阈值对比。每批结束更新一次。
